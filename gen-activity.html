IPv6 Compression

A step-by-step tutorial

    Step 1 of 7 · Get started

    Why do IPv6 addresses get shortened?

    An IPv6 address is a 128-bit number. To make it easier for people to read, we write it as 8 groups of 4 hexadecimal (base-16) digits, separated by colons. Here is one:

    2001:0db8:0000:0000:0000:ff00:0042:8329

    That is long and hard to type. So there are two simple rules that let us write the same address in a shorter form. This tutorial teaches you both rules and lets you practice using them.

    What you will be able to do

    By the end of this tutorial, you will be able to:

    • Remember the two rules used to compress an IPv6 address.
    • Understand why an address can only use the double-colon (::) shortcut one time.
    • Apply both rules to compress a full address, and expand a compressed one back to full form.

    Note for instructors: if this lesson is adapted to include narrated video or audio, captions or a transcript must be provided.

    Step 2 of 7 · Rule 1

    Rule 1: Drop the leading zeros in each group

    Each group has 4 hex digits. If a group starts with one or more zeros, you can drop those zeros. A leading zero is a zero at the start of the group, before any other digit.

    Examples of dropping leading zeros in a group
    Full groupShort formWhy
    0db8db8Drop the one leading zero.
    00000Drop leading zeros, but keep one digit. A group can never disappear on its own here — it becomes a single "0".
    004242Drop both leading zeros.
    83298329No leading zero, so nothing changes.
    Common mistake: Do not drop zeros from the middle or end of a group. The group 2010 stays exactly as 2010. Only zeros at the very start of the group can go.

    Step 3 of 7 · Rule 2

    Rule 2: Replace one run of all-zero groups with "::"

    Sometimes several groups in a row are all zeros (like 0000:0000:0000). When that happens, you can replace that whole run with a double colon: ::

    2001:db8::ff00:42:8329

    The :: above stands in for three groups that were all zero. It is a placeholder that means "fill in enough zero groups here to make 8 groups total."

    The one big limit

    You can only use :: one time in an address. If you used it twice, no one could tell how many zero groups each :: represents, and the address would be ambiguous (it could mean more than one thing).

    Common mistake: Writing 2001::db8::42 is not valid. There are two :: symbols, and a computer cannot know how many zero groups belong to each one.
    Good to know (advanced note): If an address has two separate runs of zero groups that are the same length, the standard way to write it (RFC 5952) is to compress the leftmost run and write the other one out in full.

    Step 4 of 7 · Worked example

    Watch a full address get compressed

    Here is the address from Step 1. Press the button to compress it one step at a time. Read the reasoning under each press.

    Press "Compress it" to begin.

    Reasoning, spelled out

    1. Start: 2001:0db8:0000:0000:0000:ff00:0042:8329
    2. Apply Rule 1 (drop leading zeros in each group): 0db8 → db8, each 0000 → 0, 0042 → 42. Result: 2001:db8:0:0:0:ff00:42:8329
    3. Find the longest run of all-zero groups. Groups 3, 4, and 5 are all 0 — that is a run of 3.
    4. Apply Rule 2 (replace that run with ::): 2001:db8::ff00:42:8329
    5. Check: Counting :: as the missing 3 groups, we still have 8 groups total. The compression is valid.

    Step 6 of 7 · Going the other way

    Expanding a compressed address

    You should also be able to go backward: take a short address and write out the full 8-group form. To do this, count how many groups are already written, then figure out how many 0 groups the :: must stand for so the total is 8.

    Hint: 3 groups are shown. The :: must represent 5 groups of zeros. Write each zero group as 0000 in your expanded answer.

    Reasoning: 2001, db8, and 1 are 3 groups. 8 minus 3 leaves 5 missing groups, all zero. Each group is padded back to 4 digits. Answer: 2001:0db8:0000:0000:0000:0000:0000:0001

    Pitfalls to remember

    Mistake 1: Using :: more than once in the same address. This is never allowed, even if it looks like it would save space.
    Mistake 2: Using :: to replace a run of just one zero group when it does not help. It is allowed, but the accepted style (RFC 5952) is to only use :: for the longest run, and to prefer leaving a single zero group as 0 when no run is longer than one group.
    Mistake 3: Forgetting that leading zeros can be dropped from every group first, not just the ones near the ::.
